## 🎯 目的
當需求不明確、有疑問、或需要確保品質時，使用此工作流程進行澄清。

## ⚠️ 重要原則
- **不執行任何實作**：此工作流程僅用於討論和澄清
- **必須停下來等待**：產生討論檔案後，必須等待使用者回覆
- **不猜測答案**：如果不確定，就問清楚

---

## 工作流程步驟

### 1. 分析當前情境
- 使用者提出了什麼需求或問題？
- 哪些部分是清楚的？
- 哪些部分需要澄清？

### 2. 判斷是否需要討論
**自我檢查清單：**
- [ ] 需求範圍是否 100% 清楚？
- [ ] 技術實作方式是否明確？
- [ ] 使用者期望的結果是否清晰？
- [ ] 是否有多種可能的解決方案需要選擇？
- [ ] 是否涉及重要的架構決策？

**判斷結果：**
- **如果有任何疑問**：繼續步驟 3（產生討論檔案）
- **如果完全清楚**：告訴使用者「需求已清楚，無需討論。是否要開始執行？」然後**停止**

### 3. 產生討論檔案
在 `discussions/` 資料夾建立新檔案：

**檔案命名格式：**
```
discussions/DISC-YYYYMMDDHHMM-{主題}.md
```

**範例：**
- `discussions/DISC-202501091430-VoiceFeatureScope.md`
- `discussions/DISC-202501091500-DatabaseMigration.md`
- `discussions/DISC-202501091600-UIComponentChoice.md`

**檔案內容結構：**
```markdown
# 討論主題：[簡短描述]

## 📋 背景說明
[說明當前的情境、使用者的需求]

## ❓ 需要澄清的問題

### 問題 1：[問題標題]
[詳細描述問題]

**選項（如適用）：**
- A. [選項 A 說明]
- B. [選項 B 說明]
- C. [選項 C 說明]

答：

---

### 問題 2：[問題標題]
[詳細描述問題]

答：

---

[重複以上格式...]
```

**重要：每個問題後面直接放「答：」區域，方便使用者逐題回答。**

### 4. 通知使用者並停止
告訴使用者：

```
我已建立討論檔案：`discussions/[檔案名稱]`

請在檔案中的「回覆區」回答問題。完成後，請告訴我「我已回答」，我會繼續處理。

⚠️ 在您回答之前，我不會執行任何動作。
```

**然後完全停止，不執行任何其他動作。**

### 5. 等待使用者回覆
- 使用者會說「我已回答」或類似的話
- **只有在使用者明確表示已回答後，才繼續下一步**

### 6. 讀取並總結討論結果
// turbo
```bash
cat discussions/[檔案名稱]
```

- 仔細閱讀使用者的回答
- 確認是否所有問題都已回答
- **如果使用者在回答中提出新的疑問或需要進一步澄清：**
  - **不要在原檔案中回答**
  - **建立新的討論檔案**（檔名格式：`YYYYMMDD-HHMM-{原主題}-FollowUp.md`）
  - 在新檔案中針對疑問進行詳細說明
  - 提供更清楚的選項和範例
  - 然後停止，等待使用者回答新問卷
- 如果所有問題都已清楚回答，繼續下一步

### 7. 更新文件
將討論結論整理到 `docs/` 資料夾：

**選擇適當的文件：**
- 如果是新主題：建立新檔案 `docs/[主題].md`
- 如果是現有主題：更新現有檔案

**更新 `docs/README.md`：**
- 確保新文件有被索引
- 更新目錄結構

### 8. 詢問下一步（Workflow Router）
根據討論結果，分析並建議最適合的下一步。

**告訴使用者：**

```
討論結論已記錄到 `docs/[檔案名稱]`。

根據討論結果，我建議：[AI 根據討論內容給出具體建議]

以下是所有可用的 workflow 選項：

📋 **規劃與實作：**
- `/plan` - 將需求轉換為技術規格（適合：需求已明確，需要詳細規劃）
- `/build` - 開始實作開發（適合：規格已在 02_active.md）

💡 **需求管理：**
- `/idea` - 加入待辦清單（適合：想法記錄，稍後處理）
- `/backlog` - 查看所有待辦項目（適合：想了解目前有哪些待辦）

🔍 **評估與判斷：**
- `/scope` - 判斷功能範圍（適合：不確定是否屬於當前 Story）

🚀 **部署與整合：**
- `/deploy` - 部署到環境（適合：功能已完成，需要部署）
- `/integration` - 執行整合測試（適合：需要測試 Frontend + Backend）

✅ **完成與歸檔：**
- `/merge` - 合併分支到 main（適合：功能已完成並測試通過）
- `/review` - 提取學習並歸檔（適合：專案階段完成，需要總結）
- `/commit` - AI 生成 commit message（適合：需要提交變更）

請告訴我您想執行哪個 workflow，或直接輸入指令（例如 `/plan`）。
```

**然後停止，等待使用者指示。**

## 📝 討論檔案範例

### 範例 1：功能範圍澄清
```markdown
# 討論主題：語音功能範圍確認

## 📋 背景說明
使用者提出要加入「語音功能」，但具體範圍不明確。

## ❓ 需要澄清的問題

### 問題 1：語音功能的方向
您想要的是：
- A. 語音輸入（使用者說話轉文字）
- B. 語音輸出（機器人回應轉語音）
- C. 兩者都要

### 問題 2：使用場景
主要使用場景是：
- A. LINE 聊天室內使用
- B. 網頁版使用
- C. 兩者都要

### 問題 3：優先順序
這個功能的優先級：
- A. 高（本週完成）
- B. 中（本月完成）
- C. 低（未來規劃）

---

## 💬 回覆區

答：
[請在此處回答]
```

### 範例 2：技術方案選擇
```markdown
# 討論主題：資料庫 Migration 策略

## 📋 背景說明
需要新增 `announcements` 欄位到 `brands` 表，有多種實作方式。

## ❓ 需要澄清的問題

### 問題 1：Migration 工具選擇
- A. 使用 Alembic（標準 SQLAlchemy migration）
- B. 手動撰寫 SQL script
- C. 直接修改 model 讓 SQLAlchemy 自動建立

### 問題 2：現有資料處理
對於現有的 brands 記錄：
- A. 設定 `announcements` 為 NULL（允許空值）
- B. 設定預設值為空字串
- C. 需要手動為每個 brand 設定公告

---

## 💬 回覆區

答：
[請在此處回答]
```

## 🎯 成功標準
- ✅ 產生的討論檔案格式正確
- ✅ 問題清晰具體
- ✅ 在使用者回答前完全停止
- ✅ 討論結論有記錄到 docs/
- ✅ 不執行任何實作動作

## ⚠️ 常見錯誤避免
- ❌ 不要猜測答案就繼續執行
- ❌ 不要在討論階段開始寫程式
- ❌ 不要問太籠統的問題（例如「你想要什麼？」）
- ❌ 不要一次問太多問題（建議 3-5 個）
- ❌ 不要忘記更新 docs/README.md
