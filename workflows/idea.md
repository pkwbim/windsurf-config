## 快速收集使用者故事到待辦清單

**目的**：快速將想法存入 backlog，不打斷當前工作。細節留到 `/plan` 時再補充。

### 1. 直接格式化並存入
// turbo

根據使用者提供的想法，直接建立使用者故事並加入 `pm/planning/01_backlog.md`：

```markdown
### Story-[ID] (待分類): [使用者原始描述]

**狀態**: 待細化（需執行 /plan 補充細節）

**原始需求**:
[使用者提供的完整描述]

**待補充資訊**:
- 使用者角色
- 具體功能細節
- 價值/目標
- 技術需求
- 其他相關資訊
- [AI 若有任何疑問，可以自行加在這裡，等執行 /plan 時再詢問]

---
```

**重要**：如果你對需求有任何疑問或想了解更多細節，**不要現在問**，直接將疑問加到「待補充資訊」區塊中，等執行 `/plan` 時再詢問使用者。

### 2. 分配 Story ID
// turbo
- 讀取 `pm/planning/01_backlog.md` 找出最大的 Story ID
- 新 Story ID = 最大 ID + 1
- 格式：`Story-XXX`（三位數，例如 `Story-001`）

### 3. 附加到待辦清單
// turbo
- 將新 Story 加到 `pm/planning/01_backlog.md` 的 **最底部**
- 保持原有內容不變

### 4. 完成通知
簡短回覆：
```
✅ Story-[ID] 已加入 backlog

下一步：執行 `/plan Story-[ID]` 來細化需求和規劃實作
```

## 範例輸出

```markdown
### Story-003 (待分類): 我要一個可以多人使用的小說轉語音的系統，並且還可以線上播放

**狀態**: 待細化（需執行 /plan 補充細節）

**原始需求**:
我要一個可以多人使用的小說轉語音的系統，並且還可以線上播放

**待補充資訊**:
- 使用者角色
- 具體功能細節
- 價值/目標
- 技術需求
- 其他相關資訊

---
```

## 重要原則
- **不詢問任何問題** - 直接收集
- **保留原始描述** - 完整記錄使用者的想法
- **標記為待細化** - 明確指出需要後續補充
- **快速完成** - 不打斷使用者當前工作
- **提示下一步** - 告知使用 `/plan` 來細化
