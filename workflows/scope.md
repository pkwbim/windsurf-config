## 執行步驟

### 1. 讀取當前 Story 資訊
// turbo
```bash
cat _planning/02_active.md
```

### 2. 詢問使用者
發現的遺漏或新需求是什麼？

### 3. 判斷是否為核心功能

**核心功能（符合任一條件）：**
- 沒有這個功能，Story 無法通過驗收
- 影響資料庫結構（表/欄位/關聯）
- 影響 API 設計（端點/格式）
- 影響系統架構
- 使用者無法完成主要任務

**非核心功能（符合任一條件）：**
- 優化或增強現有功能
- 可獨立開發，不影響當前功能
- UI/UX 改進
- 便利功能
- 處理極少發生的情況

### 4. 根據階段給出決策

**規劃階段：**
- 核心功能 → 立即修改 `02_active.md`
- 非核心功能 → 加入 `01_backlog.md`

**開發階段：**
- 核心功能 + 影響小（< 2h）→ 更新規格繼續開發
- 核心功能 + 影響大（> 2h）→ 停止，重新規劃
- 非核心功能 → 加入 `01_backlog.md`

**測試階段：**
- 核心功能 + 嚴重 → 停止，評估是否 rollback
- 核心功能 + 輕微 → 快速修正
- 非核心功能 → 加入 `01_backlog.md`

### 5. 輸出決策

```markdown
# 範圍判斷結果

## 遺漏/需求
[描述]

## 判斷
- 類型：核心功能 / 非核心功能
- 階段：規劃中 / 開發中 / 測試中
- 原因：[為什麼是/不是核心功能]

## 決策
[立即處理 / 停止重規劃 / 加入 Backlog]

## 行動步驟
1. [具體步驟]
2. [具體步驟]
```
